# Risk Analysis — in-season-ops

**Date:** 2026-08-30
**Design doc:** [2026-08-30-in-season-ops-design.md](../specs/2026-08-30-in-season-ops-design.md)
**Tier:** 2
**Techniques run:** A (Premortem Heavy), C (Assumption Extraction), H (Dependency Graph / Resource Contention) — executed by parallel Opus subagents; synthesized in main thread.

## Headline findings

1. **Live production bug found during analysis:** `ingest_nflverse.py` is scheduled in no launchd plist and no crontab — 1209h (50 days) stale — and `morning_briefing.py` marks it `[OK]` because the `ingest_runs` health check tests status but never age. The design's "works today, no Yahoo needed" foundation does not currently work.
2. **Zero high-criticality assumptions are held with high confidence** (0 of 25). Four zero-cost tests (~2 hours total, all doable from the 2025 Yahoo transaction log + settings page, no API needed) resolve seven of the most dangerous ones. Do these before any code ("Step 0").
3. **Three cross-cutting root causes:** (a) the system guards data *absence* but not *degraded-quality presence* (semantic drift, precision loss, partial publishes); (b) Yahoo mechanics were inferred from settings pages, never observed from transaction logs; (c) the output channel is a 24-hour pull-based digest while the windows being arbitraged are minutes wide.
4. **The backtest as specced is impossible:** Sleeper trending has no historical endpoint. Begin archiving `market_trends` daily immediately so mid-season validation becomes possible; swap the 2025 backtest baseline to league add-timestamps / FP news timestamps.

## Design-change directives for the ADR

1. Insert **Step 0** (observed-mechanics tests) before build step 1; add the sim-farm ceiling test as the gate on steps 3–4.
2. Reverse league-state polarity: **manual-first, API-as-optimization** (matches the documented draft-day lesson).
3. Replace fixed wall-clock scheduling with a **league-clock spec** (written deadlines) + data-readiness triggers; expect a dual cadence (Mon-evening claims brief, Tue trends).
4. Add the **third data state** (OK / KNOWN-LAGGING / BROKEN) and semantic sanity gates on every ingest; urgency score fails closed.
5. Admit windows 2+3 are latency-bound: fund the minimal push channel (~3 pushes/wk cap) or formally de-scope them.
6. Add an explicit **QB-repair objective** as a first-class system goal, not a watchlist parenthetical.
7. Start the `market_trends` archive pull immediately (backtest feasibility).
8. Fix R1 (nflverse scheduling + age check) before any new code.
